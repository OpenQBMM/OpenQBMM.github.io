Get started

Installation

OpenQBMM is compiled against an existing OpenFOAM installation built from sources. Install OpenFOAM first, then build OpenQBMM in the same shell environment.

Requirements

  • OpenFOAM v2606, built from sources
  • A C++ toolchain and git
  • Linux, or Windows 10/11 with WSL
  1. 01

    Source the OpenFOAM environment

    Every build and every run happens in a shell where the OpenFOAM environment is loaded. Adjust the path to your installation.

    source $HOME/OpenFOAM/OpenFOAM-v2606/etc/bashrc
  2. 02

    Clone the repository

    Clone into your OpenFOAM user directory, or anywhere you keep sources.

    git clone https://github.com/OpenQBMM/OpenQBMM.git
cd OpenQBMM

    This downloads the whole repository, about 156 MB. To build OpenQBMM only, a smaller download of about 5 MB is enough.

  3. 03

    Build

    The build script compiles the libraries, then the solvers and utilities. Use -j to compile in parallel.

    ./Allwmake -j
  4. 04

    Run a tutorial

    Copy the tutorials out of the repository, with the AllrunFunctions their scripts read, and run one to confirm the build works.

    mkdir -p $FOAM_RUN/OpenQBMM
cp -r AllrunFunctions tutorials $FOAM_RUN/OpenQBMM
cd $FOAM_RUN/OpenQBMM/tutorials/pbeFoam/aggregationBreakup
./Allrun

A smaller download

Most of the size of the repository is not code: the meshes of the convergence studies of the tests and the reference data of the validation cases. A partial, sparse clone downloads the history without the contents of the files, and checks out only what the build and the tutorials need, about 5 MB instead of about 156 MB. Run these in place of step 02:

git clone --filter=blob:none --sparse https://github.com/OpenQBMM/OpenQBMM.git
cd OpenQBMM
git sparse-checkout set src applications bin tutorials
How it works
--filter=blob:none downloads the commits and the directory listings without the contents of the files, which git fetches when a directory is checked out. --sparse starts with the files at the top of the repository only, Allwmake and the scripts it reads among them, and sparse-checkout set adds the directories named. Checking out more, or another branch, needs a network connection. Git 2.26 or later is needed.
The unit tests
git sparse-checkout add test brings the whole of test, 280 MB of it the meshes of the convergence studies in test/univariateMomentAdvection. The unit tests need only the two utilities beside those meshes, so this adds them in about 4 MB: 
git sparse-checkout add \
    $(git ls-tree -d --name-only HEAD test/ \
      | grep -v univariateMomentAdvection) \
    test/univariateMomentAdvection/setMoments1D \
    test/univariateMomentAdvection/setMoments2D
The validation cases and the whole tree
The tiers of the validation run cases from tutorials, validation and test, so they need all three, the convergence studies included. The first command adds the validation cases, about 180 MB; the second checks out the whole tree: 
git sparse-checkout add validation
git sparse-checkout disable

Building for development

What a developer needs beyond the four steps above. To test and validate a build, see running the tests and the validation.

Where the build goes
The libraries and the applications go to FOAM_USER_LIBBIN and FOAM_USER_APPBIN unless -prefix or the variables FOAM_MODULE_LIBBIN and FOAM_MODULE_APPBIN name another place; FOAM_MODULE_PREFIX=false skips the build. 
./Allwmake -j -prefix=<dir>
./Allwclean
A packaged OpenFOAM
With the openfoam.com packages, the build runs in the environment of the package without sourcing it: 
/usr/bin/openfoam2606 ./Allwmake -j
One library or one solver
After a change to a source file, only what contains it needs building again: 
wmake libso src/quadratureMethods/momentInversion
wmake applications/solvers/populationBalance/pbeFoam
After a change to a header
A change to the layout of a class, a member or a virtual function added or removed, has to reach everything compiled against it. A library, a solver or a test built against the old layout loads without complaint and then calls the wrong function or crashes. Build everything again, the tests included: 
./Allwmake -j && ./test/Allwmake -j
Build order
src/Allwmake builds the libraries in the order of their dependencies, from Vandermonde to populationBalanceModels. A library reaches the headers of another through its lnInclude directory, written as a relative path in Make/options, so a new library is inserted in that list after the ones it uses.
Several OpenFOAM versions
The sources compile on earlier openfoam.com releases than the one they are developed on. Code that depends on the version is guarded with #if (OPENFOAM >= NNNN), in the sources and in Make/options alike.
A debug build
OpenFOAM keeps the debug and the optimised builds apart. Load the environment of the debug build of OpenFOAM, then build OpenQBMM in it as above: 
source $HOME/OpenFOAM/OpenFOAM-v2606/etc/bashrc WM_COMPILE_OPTION=Debug

Platform notes

Linux

Build from sources

Install OpenFOAM from sources following the instructions for your distribution, then build OpenQBMM in the same environment.

Windows 10 / 11

Windows Subsystem for Linux

WSL runs OpenQBMM without installing a Linux distribution directly. Recommended for rapidly testing the capabilities of the code, and convenient for developers who run their simulations on remote HPC clusters.
